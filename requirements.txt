# --- libGL / opencv-contrib-python fix, corrected version ---------------------
# The previous fix here (mediapipe installed with --no-deps, but still listed in
# this file too) did NOT actually work: pip's resolver evaluates a package's
# declared dependencies as part of resolving requirements.txt even when that
# package is already installed. So "mediapipe==0.10.33" appearing anywhere in
# this file -- pinned or not -- was enough for pip to see it needs
# opencv-contrib-python (the GL-linked build, confirmed directly against
# mediapipe's own package metadata) and install it anyway, colliding with
# opencv-python-headless below and crashing `import cv2` with libGL.so.1 missing.
#
# THE FIX: mediapipe is not listed in this file at all. It's installed as a
# fully separate, standalone command in nixpacks.toml's install phase, which
# never triggers a resolution of its dependencies. Verified directly: with this
# exact file, opencv-contrib-python never gets installed, and cv2 + mediapipe
# both import and function correctly together.
#
# torch pinned to 2.2.2, numpy pinned below 2.0 -- together, deliberately.
# PyTorch wheels before ~2.3 use the NumPy 1.x C ABI; mixing with NumPy 2.x
# crashes the first time torch touches a numpy array. If you want NumPy 2.x,
# upgrade torch to >=2.4 instead -- untested here, re-verify /v1/restore after.
#
# CPU-ONLY torch wheel, deliberately -- Railway has no GPU, and plain
# `torch==2.2.2` from PyPI installs several GB of unusable CUDA packages.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.2.2+cpu
numpy>=1.26,<2

opencv-python-headless>=4.9,<4.11
