# torch pinned to 2.2.2, numpy pinned below 2.0 — together, deliberately, not
# separately. PyTorch wheels built before ~2.3 use the NumPy 1.x C ABI; installing
# them next to NumPy 2.x doesn't warn, it hard-crashes the first time torch touches
# a numpy array ("RuntimeError: Numpy is not available"). This exact crash was
# reproduced and fixed here. If you want NumPy 2.x (e.g. for another dependency),
# upgrade torch to >=2.4 instead — untested in this repo, verify /v1/restore again
# before trusting it.
#
# CPU-ONLY torch wheel, deliberately. Railway (and Render/Fly/Heroku on standard
# plans) has no GPU, but a plain `torch==2.2.2` from PyPI still installs the CUDA
# build plus ~3-4 GB of nvidia-*-cu12 packages that can never be used there —
# it just makes the build slow and, on tighter build-resource plans, can fail
# outright from disk pressure during the build step. The +cpu wheel skips all of
# that (~190 MB instead of several GB) and runs identically for this project,
# since nothing here does training — only inference.
# If you deploy to a machine WITH a GPU: delete the two lines below this comment
# block and instead run `pip install torch==2.2.2` (plain, from PyPI) followed by
# a `pip install -r requirements.txt`, or see https://pytorch.org/get-started/locally/
# for the exact CUDA-version index for your driver.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.2.2+cpu
numpy>=1.26,<2

# opencv-python-headless and mediapipe pull opencv-contrib-python as a transitive
# dependency; recent versions of both require numpy>=2, which conflicts with the
# pin above. Capping opencv-python-headless below 4.11 keeps pip's resolver on
# versions built for numpy<2 — confirmed with `pip install --dry-run` against this
# exact file.
opencv-python-headless>=4.9,<4.11
mediapipe>=0.10.15

fastapi>=0.110
uvicorn[standard]>=0.29
python-multipart>=0.0.9
